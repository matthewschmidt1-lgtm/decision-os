# Decision OS

A training site for CPG sales. Reps practice real commercial decisions, then see the evidence, reasoning, and principle behind the recommendation. The goal is to teach decision algorithms (expected value, Bayesian updating, value of information, marginal analysis, bandits, decision trees, utility trade-offs) through the decisions reps already make, not as theory.

- Live: https://decision-os-production-5b4a.up.railway.app/
- Repo: github.com/matthewschmidt1-lgtm/decision-os (branch `main`; pushing deploys to Railway automatically)

## Hard constraints

- **Zero build step.** Vanilla ES modules, plain CSS, hand-drawn SVG. No framework, no bundler, no runtime dependencies. Don't introduce npm tooling: this Mac has no Node, npm, Homebrew, `gh`, or `railway` CLI.
- **Every recommendation shows its reasoning.** Never display an answer without the logic behind it. Never reveal the preferred option before the user chooses (decisions and practice scenarios both hide it until a choice is made, including on a revisit). The expected volume and margin on decision option cards stay visible before choosing: that's deliberate, so the user compares options rather than guesses.
- **All data is illustrative** and must be labelled as such where it appears. Numbers must be internally consistent across pages (e.g. Brand B's share of trade is 32% everywhere).
- **Design language:** Apple / Mike Markkula restraint. Tokens live in `css/tokens.css`: ivory `#F5F5F0`, ink `#171717`, muted `#7B7B76`, one accent `#2457D6`. Green, amber, and red are for meaning only. One primary question per screen. Must work at 375px with no horizontal scroll.

## Run and test

```bash
python3 scripts/dev.py 4173
```

Dev server with SPA fallback, no-store caching. Preview at http://localhost:4173/.

Model tests run in the browser at http://localhost:4173/tests/run.html (an import map shims `node:test`). `npm test` also works anywhere Node exists. Add a test when you change a formula in `js/sim.js` or `js/models.js`.

After changing anything visible, check it in the browser at desktop and 375px, and check the console for errors. ES modules can be cached in the preview tab; reload before trusting what you see.

## Deploy

Push to `main`. Railway runs `scripts/serve-site.sh`, which copies only the public site (`index.html`, `robots.txt`, `sitemap.xml`, `serve.json`, `css/`, `js/`, `public/`) into `dist/` and serves it with `npx serve -s`. Anything outside that list is not deployed. If you add a new top-level public file, add it to that script.

`serve.json` sets security headers (CSP, X-Frame-Options, HSTS, Permissions-Policy, COOP) and `Cache-Control: no-cache` on JS/CSS so updates show on the next visit. The CSP allows scripts from `'self'` only and fonts from Google Fonts. Don't add inline scripts or other third-party origins without updating it.

## Conventions and gotchas

- **Lookup maps** (`brandById`, `scenarioById`, etc.) use `byKey()`, which builds prototype-free objects so route ids like `__proto__` 404 instead of crashing. Use `byKey`, not `Object.fromEntries`, for any id lookup.
- **Scenario data shape:** `evidence` rows are `[label, value, tone?]`. A value containing ` · ` renders as chips or a comparison card, so keep the part order consistent across compared options. Each scenario has exactly four options with one `quality: "best"`. Best-answer positions are rebalanced automatically at the bottom of `scenarios.js`. Every scenario must belong to exactly one track.
- **Brand ROI fields:** `gm` is gross margin %, `tradeK` is annual trade $K, `avgRoi` is past incremental gross profit per $1 of trade, `r0` is the return on the next $1 and `r0Lo`/`r0Hi` its plausible range (wider for brands with less history), `k` is how fast returns diminish (in $K; it scales with the brand's spend, roughly 60% of it, so big brands flatten over hundreds of thousands, not tens), and `hoursNow` is selling hours per month (of 40). `margin` is the margin trend in pts and `trade` is trade growth %. Returns are measured before the trade cost, so $1 is breakeven.
- **Portfolio is a four-quarter game**, not a set of analytical views. Loop: request → decide → run the quarter → results → reallocate → year-end review. The player moves $500K of trade a quarter in $10K chips (− puts a chip in "Free trade", + takes one; overspending is impossible), sends up to 2 scouts a year, and answers one real-life request a quarter (Kroger end-cap, distributor allowance, one restaurant menu slot, a year-end load-in). One lever unlocks per quarter: channel focus (Off-premise / Both / On-premise per brand) in Q2, field days (40 a quarter) in Q3. Algorithms are only named in the year-end review.
- **Score and tiers:** the score is gross profit after trade against running last year's plan all year, counting what carries into next year (on-premise work pays partly next quarter; the load-in borrows from next year). Bronze/Silver/Gold are set from what the reassess-every-quarter strategy (`evidencePlans`) achieves, so they stay winnable if you retune numbers.
- **The simulation is replayed from the saved plans** (`localStorage` key `decision-os:sim:v2`), so there is no hidden state to drift. Noise is seeded, so the same decisions always give the same year. Forecasts use the team's beliefs; results use the hidden truth; beliefs update only in the channel you funded or the brand you scouted. Growth is measured against last year's plan, so running that plan grows each brand at its stated rate.
- **Designed lessons live in the world (`BASE`, `TEAM`, `VARIANTS` in `sim.js`):** each channel has its own response curve; big brands have an off-premise shelf floor (cut below it and base volume goes); one brand's off-premise chain is broken (promotions load the distributor, which books revenue first and unwinds in Q3 unless a scout finds it); one small brand is a sleeper on-premise. Year two (`VARIANTS[1]`) moves the break and the sleeper so a second play isn't a memory test. If you change the numbers, keep `tests/sim.test.mjs` passing: both years need a winnable gap, an earnable tier, and an avoidable unwind.
- **Decisions (`decisions` in `data.js`, `pages/decision.js`) are four deeper calls, one round of change each, built on that decision's own algorithm:** every decision states an `objective` (weights over volume, margin, revenue, distribution) that must rank `preferred` first. Only the utility decision (Brand B) has `shifts` (VP, CEO) with importance sliders, because weighing objectives is its lesson. The others have one `twist`: an offer or push whose options list their parts (`lines`, with odds `p` where relevant); the learner commits, then sees each option's worth. Marginal = count everything the extra dollars buy, VOI = act now vs find out first, EV = chance × value, added up. Each round's `best` must be the winner and be named in its `lesson` (tested in `models.test.mjs`). `track` links to the Practice track that trains it.
- **Learn lessons are drills (`drill` on a lesson in `js/lessons/index.js`, rendered by `drillPage` in `pages/lesson.js`):** one call, one twist, one rule. Situation as a lead sentence plus bullets (`situation: { lead, points }`), every number written out → 2–4 options (math hidden until a pick) → verdict with the trap → one change, pick again → the rule, its flip point, the formula in small type, a Monday line, links to the Practice track and the Decision. Option values are $K and must be consistent with the Decision pages' data. Every lesson is a drill now (the old Concept/Try it/See it/Apply page is gone); the `concept`/`sales`/`apply` fields are kept as reference copy only. `estimate: true` rounds ask for a number and name `best` explicitly; `show` overrides the $K display. After the second round, "The rule in one picture" (`js/lessons/pictures.js`, one still SVG per slug) draws the rule from the same numbers, with the flip point and the learner's two picks; any change to a drill's numbers must be mirrored there. The interactive widgets in `js/lessons/widgets.js` remain in use on Decision pages.
- **Module 2 · Conversation (`js/scenarios2.js`, `pages/sell.js`, `pages/sell-scenario.js`, routes `/sell`, `/sell/:id`, `/sell/summary`):** same scenario shape and page flow as Module 1, plus `buyer` (the line that opens the meeting, shown as a quote), `then` (how the conversation continues after the strongest move) and `pattern` on an option (a key into `patterns`: the selling habit that pick reveals, e.g. pitching before discovering, giving without getting). Results are stored separately (`results2` in the store) so Module 1 counts and scores never include Module 2. Patterns roll up into `families` (concede, tell, noask, buck, link; `comply` is a note, not counted) and best options carry a `strength`. `habitSummary` in `pages/sell-scenario.js` always reads all played results, re-derives tags from the current data by option label, and says less when there is less to go on: "early read" under 5 plays, skill line only with 3+ plays per skill and a 15-point gap, a habit only with 3+ tagged picks, a quarter of tagged picks and a clear lead (ties are named). Hub bars read Early under 3 plays in a skill. Module 1 pages are untouched apart from the entry card at the bottom of Practice; keep it that way. Copy rule for Module 2: plain English, US spelling, one takeaway per scenario, the best option asks or trades rather than pitches or concedes, and option labels stay under about 150 characters so the strongest answer is not simply the longest. Beverage-alcohol cases never trade anything of value for a placement (tied-house), including staff incentives or conditional distributor pricing.
- **Appearance (`css/tokens.css`, `js/theme.js`, header sun/moon button):** every colour is a token on `:root`; the dark set (warm charcoal `#1C1C1A`, off-white ink) is defined twice, once under `:root[data-theme="dark"]` and once under `prefers-color-scheme: dark` for `:root:not([data-theme="light"])`. `theme.js` is a plain script in `<head>` (runs before paint; the CSP allows same-origin scripts, not inline) that applies the stored choice (`decision-os:theme` = auto | light | dark), updates `theme-color`, and wires `#theme-toggle` in the header: one press flips the scheme you're looking at and stores light or dark; the icon shows what a press gives you (moon while light, sun while dark). Auto is only the state before the first press. Next to it, `#display-trigger` opens the "Display and accessibility" popover (`.display-panel`, static markup in `index.html`, wired in `theme.js`): Text size A−/A+ (0.9–1.4, stored as `textScale` in `decision-os:display` and applied as `--text-scale` on `html`, so rem-based type scales), Night reading (the same theme setting as the sun/moon), Reduce motion (`data-motion="reduce"` on `html`: `base.css` zeroes animations and transitions; JS checks go through `reducedMotion()` in `ui.js` or `reduced()` in `portfolio/fmt.js`, never `matchMedia` directly) and Higher contrast (`data-contrast="high"`: darker `--ink-2`/`--ink-3`/`--muted` and stronger `--line`s, declared for light, chosen dark and device dark). The panel is 340px wide (or the viewport minus 32px) and fits an iPhone SE with the nav row below it. Header nav: Practice, Sell (Module 2, `/sell`), Accounts, Learn; footer: Learning Principles, Practice, Sell. Decisions (`/decisions`) and Portfolio (`/portfolio`) are deliberately unlisted in the navs but still routable; Portfolio is reached as "Run the Business" in the Display and accessibility panel. Never hard-code a colour in CSS or JS; add a token (gold/tier tokens exist for Portfolio achievements). The inverted "principle" card uses `var(--ink)` on `var(--bg)` and flips with the scheme by design.
- **Portfolio readouts agree (`forecastQuarter` in `js/sim.js`):** the forecast counts the on-premise and field-day return that lands next quarter separately (`carryNext`), includes the menu bonus, and exposes both channel marginals (`mOn`, `mOff`). The Decide screen shows "this quarter ≈ X · Y lands next quarter", both channels under Next $10K, and a split line above the toggle ("Both" = the brand's on-premise revenue share). Results show a score waterfall from `attribution(q, habitQ)` (each brand against the same brand under last year's plan, with the reason) and the insight line is built from it unless the quarter had a real event (unwind, load-in). Request funding is refunded when the answer changes (`st.funded`). "Knew when to stop" ignores $10K steps that were covering a shelf floor.
- **Portfolio market read (`MARKET`, `marketRead`, `marketOutcome` in `js/sim.js`):** one or two signals a quarter, each of three kinds with a different right answer: demand down (base and that channel's response fall: don't chase it), response down (promotions lift less: move the money), shelf under attack (the off-premise floor rises: defend it). Signals change both the forecast and the simulation, so the card's Next $10K reflects them; the Decide screen explains the signal in plain words and the results say what the player did about it and what it returned. Results include a return table (last $10K returned per brand and channel, with a verdict: room to add / near the top / past the top / below the shelf floor); the forecast-vs-actual charts sit under a disclosure. Last quarter's verdicts appear on the next Decide card. The year-end benchmark is labelled "Scout early, then follow the forecast" with the top three places it differed (`differences`).
- **Portfolio Flight Deck (`js/pages/portfolio.js` + `js/portfolio/*`, `css/flightdeck.css`):** the page is a cockpit. Top: the midnight deck (horizon = banked score as altitude against last year's plan, tier contours, this quarter's dashed team forecast; instruments for score, free trade, field days, scouts, Run). Decide: the briefing (`.fd-brief`: What they say, Facts, Team estimate, Open questions, Your answer) with "The market this quarter" beside it, then the eight-tile map and the inspection panel (a bottom sheet under 1024px) holding the funding instrument and reconnaissance ("What the team doesn't know": each channel's range from `S.channelRead`, team note, scouts left, "Reports back after the quarter."). Run draws the quarter's horizon segment across its months (~3s, Skip to results, background-tab timeout; instant under reduced motion). Results are `debriefView` in a fixed order: landing (banked and in the air apart), waterfall (+ carry split), the quarter's events listed statically, request, achievements, market, return table, scout reports (range before → after), chain cards, what the team learned, charts in a disclosure. Year end: the horizon adds the "Scout early, then follow the forecast" path (evidencePlans, per-quarter gp minus habit, then its year-end score), dashed; the review blocks keep their order. `js/sim.js` is frozen apart from the read-only `channelRead`; `tests/sim-baseline.test.mjs` must never move.
- **Portfolio dash rhythm (`css/flightdeck.css`, "Dash rhythm" block):** the page is read as chapters, not one column. Inside `.fd .sim-flow`, every direct child that opens with an `.eyebrow` (plus `.fd-wfwrap`, `.disclose`, `.sim-go`, `.fd-briefrow`, `.fd-cockpit`) gets a fender-line divider (an SVG mask over a gradient: accent for the first 40px, then the hairline, fading out) and its eyebrow a CSS-counter numeral (`01`, `02`…); the first child is the chapter head and gets neither. Panels carry a lit top edge (`--lip` for house panels, `--fd-lip` for the cockpit); the deck sits under a radial hood. The Score instrument is a ring dial filled toward Gold (`fd-dial` in `deck.js`; callers pass `gold` because the instruments can render before the horizon). Keep it quiet: one line, one numeral, one highlight per chapter; no new ornament.
- **All plan edits go through `js/portfolio/plan.js`** (`stepTrade`, `setTrade`, `moveTrade`, `stepDays`, `setFocus`, `toggleScout`, `pickAnswer` with its fund/refund, `applyLocks`, `takeNextScout`, `nextDraft`, `resetTo`). It is pure: it imports only `sim.js` and `fmt.js`, never the DOM and never `app.js` (the tests import it). `tests/plan.test.mjs` checks it against the old page code; `tests/drive-mine0.js` drives the live page through the mine0 fixture (run it by hand from the console). The briefing's Team estimate runs the same `pickAnswer` on a copy, so the estimate is the plan the button would leave.
- **Flight Deck colours are scoped `--fd-*` tokens** in `tokens.css` (sky, panel, ivory, terrain, cyan, amber, red), re-declared as the house tokens inside `.fd-deck`, `.fd-map`, `.fd-panel` so reused components render dark. Only the cockpit is midnight, in both schemes; prose (briefing, debrief, review) stays on the house background. Cyan = your inputs and the team's forecast; amber = caution or uncertain (market signal, floor about to break, unanswered request, low-confidence fog); red = loses money or realised harm; terrain green = earns. Colour is never the only cue. Mono for instrument labels and readouts. Motion only on a state change (path draw, 200ms sheet slide, 150ms tile highlight); nothing loops; no single-key shortcuts.
- **Portfolio honesty rules:** attribution is only `attribution()` lines plus the carry split (`q.stateBefore.carry[id] − habitQ.stateBefore.carry[id]`); never write "because" beyond that. Wherever confidence isn't High show a range, labelled "the team's range" (ranges are belief ± spread, not truth intervals). Every forecast readout says ≈ or "team forecast"; results show actuals next to forecast. Mid-year, banked and in-the-air are shown separately. Never preview: `world().truth` beyond what the forecast already uses; which brand is broken or the sleeper, `state.load`, `trend`, `FIXED`; future `quarterEvents`, the Q3 unwind, the load-in's borrowed amount, any `simulateQuarter` output before commit; finding text before the quarter closes; later quarters' market signals; menu bonus mechanics beyond `onRead`. The load-in's estimate (about +$90K) never appears without "what does it cost next year?" beside it, because `forecastQuarter` doesn't count `borrowed`. Briefing facts quote a chain card only if the last results showed it (`shownChains`).
- **Portfolio open questions (known, deliberately not fixed; don't "fix" one silently):** 1 the request's scout and a card scout can double-count against the limit (the readout is `scoutsLeft − plan.scout.length`; `simulateQuarter` keeps `plan.scout` first and drops the request's; a muted note says so); 2 "Knew when to stop" is marked missed in Q1 for inherited money; 3 the market outcome can say "Distribution held" while the chain card shows ACV −1.0; 4 `attribution` can label carry as "on-premise trade"; 5 ranges are belief ± spread, not truth intervals; 6 the load-in forecast ignores `borrowed`; 7 the field-day `nextDay` includes lag while `evidencePlans` discounts it in Q4; 8 team notes stay static after a scout; 9 the "React" tendency can fire inside the noise band; 10 review "Diminishing returns" uses the true curves and flags inherited Q1 money; 11 dead code `defaultAnswer`/`pts` in `sim.js`, and `marketRead` uses the BASE floor; 12 the blended and channel headlines can disagree; 13 average vs marginal labels differ between the chain card and the return table; 14 "Reset to" keeps a paid request's answer but not the money it took, so trade can exceed budget (the free-trade instrument shows "over budget"); 15 `main` is `aria-live=polite` (the stage opts out with `aria-live=off` and one status line speaks).
- **Scenario pages after a UX audit (both modules):** picking an answer scrolls the strongest move (`.option.choice.preferred`, badge included) to just under the sticky header so the answer stays in view with the verdict beneath it, and moves focus to the verdict heading (`show()` in `pages/scenario.js` and `pages/sell-scenario.js`). Unchosen options keep readable text and fade only the letter badge. The "Why?" layer shows an "Evidence used" line (`evidenceUsed` in `ui.js`: rows whose label words or figures appear in the reasoning and best feedback) instead of repeating the evidence block; prose in `.verdict`, `.layer` and the Module 2 disclosure is capped at 68ch. Comparison cards split `yours 33%` into an owner word and a bold figure (`li.pair`) and go two-up under 480px; card titles reserve two lines so rows align. Conversation pages size the buyer's quote up (20px, `says(..., { live: false })` so it is not a live region) and the situation headline down (`.sell.has-quote`). `--ink-3` is the grey for small text that still carries meaning (metric labels, caveats, helper lines); `--warn` and `--good` were darkened to clear 4.5:1 on the sunk card in light mode.
- **Module 2 progression (`js/sell-progress.js`):** first tries are the score; a replay (`recordReplay2`) shuffles the options per attempt and can mark a case Fixed. Track cards read Clean / Fixed / Complete · n of N strongest. Nine milestones named for selling behaviors, announced on the scenario page the moment they are earned and listed on the hub. A level (Bronze / Silver / Gold) mirrors Portfolio. "Challenge, round 2" builds a five-case set from the weakest skill and Revisits (`sell2.challenge2` in the store, runs recorded on its summary). Compliance picks (`pattern: "comply"`) are always weak and get the headline "Not allowed. Here's what is." Scenario `cost` lines show what a weak pick cost; `follows` links a round-two case from its round one. Good scores 0.5.
- **Module 3 · Manage (`js/scenarios3.js`, `pages/manage.js`, `pages/manage-scenario.js`, `manage-progress.js`, `manage-pictures.js`, routes `/manage`, `/manage/:id`, `/manage/summary`, all behind the soft gate):** thirty management cases built from the six books on the author's site (`docs/module3-proposal-v3.md` is the source; v1, v2 and `docs/module3-review.md` are the history). Shape is Module 2's plus `who`, `theme`, `trade` (the two values in tension), `lens`/`tension` ([book key, the author's lesson], shown in the Why layer without the book name), `voice`, `pause`, `leans` on sound options (one of the case's two trade values) and `picture` ({ kind, left, right, marks [key, 0–100, caption], after, note }). `channel` and `category` are gone. Scoring: best and good are both sound (`qualityScore3` 1/1/0), "strongest" counts best only, no percent and no tiers; the hub bars read "n of m sound"; the summary (`summary()`) names the values you reach for (from `leans`, once a value was on the table 3 times), the habit family under pressure (Module 2's thresholds) and what the strongest added when you picked a good one. Results live in `results3`/`manage3`, kept apart from Modules 1 and 2. **The picture is drawn only after the pick** (`drawPicture(base, picked)` keys marks by option identity, so replay shuffles never move a mark) and marks only the learner's pick and the strongest; six kinds (axis, belief, check, curve, forecast, hours) map to Learn lessons through `algorithmFor`, which is the "Learn the algorithm" link. Feedback headings: best "A strong way to do it.", good "Defensible…", weak "A common move under pressure." Module 3 is listed as "Manage" in the header and footer navs, behind the soft gate. `docs/*.html` are gitignored reading copies.
- **Soft password gate (`js/gate.js`):** `/accounts`, `/accounts/:id`, the `/learn` library page (individual lessons stay open) and the Practice "All N scenarios" list ask for a password in a `<dialog>`; one correct entry unlocks both for the browser session (`sessionStorage`). The router calls it in `navigate()` and `render()`, so every route in is covered. The check runs in the browser and the password ships in the code: it keeps casual visitors out and is not real security.
- **Accounts opens with a rule, not a list (`js/accountsViz.js`):** the learner picks the rule that decides where 20 visits go: the habits reps really use (biggest accounts, the accounts I always see, most likely to say yes, closest to my route, most overdue) or chance × value − cost. Route distance and days since the last visit are derived from the account id (`miles`, `daysSince`), not the shared random stream, so the territory numbers don't move. Every rule is scored by the expected value of its top 20, so expected value always wins by construction; the ranked table stays hidden until a rule is picked or skipped (links with `channel`, `sort` or `roi` skip the gate). The 84-account animation starts when it scrolls into view and rings the chosen rule's 20.
- **Achievements (`ACHIEVEMENTS`, `achievementStatus` in `sim.js`) are judged on what the player could see, never hidden truth:** "Knew when to stop" uses the team's forecast, not the true curves. They work mid-year (`got` / `open` / `missed`), show in a panel on every decide screen, and are announced on the results screen. `evidencePlans` must earn all seven in both years (tested).
- **Open Graph images** are rendered with macOS Quick Look (`qlmanage`) from an SVG on a square canvas, then cropped with `sips` to 1200×630. Give a new image a new filename so iMessage doesn't show a cached preview.
- **Canonical, sitemap, and robots** use the Railway domain. Update all three if the domain changes.
- **Commits** end with a `Co-Authored-By` line. Push only when asked, or when finishing a change the user requested.
